This page is the catalogue of rules, and a public roadmap. Rules marked _Available_ or _Partial_ work in the extension today. Rules marked _Planned_ do not exist yet; they are listed with a phase number, and lower phases come first. The rule names, their options and the config file shown here are a draft and may still change.

Today the formatter and the checks run without configuration. [Formatting](/vscode-ruby-templates/guides/formatting/) describes what the formatter does, and the [diagnostics reference](/vscode-ruby-templates/reference/diagnostics/) lists every code the checks report.

## How to read an entry

- **Type.** An _autofix_ is a formatter rule that rewrites the template. A _warning_ is a check that reports a problem and rewrites nothing.
- **Rendered output.** _Safe_ means the rule leaves the rendered page as it is: it only changes whitespace the browser ignores, or changes markup into an equal form. _Not safe_ says what can change.
- **Examples.** An autofix shows the template before and after. A warning shows a flagged template and a fine one. The examples of available rules were produced by `ruby-templates format` and `ruby-templates check`; the ones of planned rules are written by hand.
- **Defaults.** The planned formatting rules are off until you turn them on, so a file is never changed unless you ask. The planned Rails checks are on.

## Planned configuration

Planned rules are configured in a `.ruby-templates.toml` at the project root. This file is not read yet; the extension ignores it. Each rule is a table named after it, with the department and the rule joined by a dot:

```toml
[Layout.EmptyLines]
enabled = true
max = 1
```

A rule has one name in every language it applies to: `Layout/EmptyLines` covers ERB, Haml and Slim. To change it for some files only, give it `include` or `exclude` globs, as RuboCop does:

```toml
[Layout.EmptyLinesAroundElementBody]
enabled = true
exclude = ["**/*.haml", "app/views/legacy/**"]
```

A `.ruby-templates.toml` in a subfolder applies to the templates below it and overrides the one above for the rules it names. The same file is read in the editor and by `ruby-templates check` and `format`; settings in VS Code still apply on top.
