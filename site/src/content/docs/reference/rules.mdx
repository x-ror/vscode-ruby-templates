This page is the catalogue of rules, and a public roadmap. Rules marked _Available_ or _Partial_ work in the extension today. Rules marked _Planned_ do not exist yet; they are listed with a phase number, and lower phases come first. Rule names are the diagnostic codes, and the config file described below is read for the rules that exist.

The formatter and the checks work without configuration, and a `.ruby-templates.toml` changes them. [Formatting](/vscode-ruby-templates/guides/formatting/) describes what the formatter does, and the [diagnostics reference](/vscode-ruby-templates/reference/diagnostics/) lists every code the checks report.

## How to read an entry

- **Type.** An _autofix_ is a formatter rule that rewrites the template. A _warning_ is a check that reports a problem and rewrites nothing.
- **Rendered output.** _Safe_ means the rule leaves the rendered page as it is: it only changes whitespace the browser ignores, or changes markup into an equal form. _Not safe_ says what can change.
- **Examples.** An autofix shows the template before and after. A warning shows a flagged template and a fine one. The examples of available rules are run through `ruby-templates format` and `ruby-templates check` by the tests; the ones of planned rules are written by hand.
- **Defaults.** A formatting rule says whether it is on by default. `Layout/TrailingEmptyLines` is, for Haml and Slim; the others, `Layout/EmptyLines` among them, are off until you turn them on, so a file is never changed beyond what the entry says unless you ask. The planned Rails checks are on.

## Configuration

Rules, and the switches that VS Code has as settings, are configured in a `.ruby-templates.toml`. The editor, `ruby-templates check` and `ruby-templates format` read the same file. A rule is a table named after it, with the department and the rule joined by a dot (`["Html/ImgAlt"]` in quotes is an error, and the message says how to write it):

```toml
[Html.ImgAlt]
enabled = false
```

A department table with only `enabled` switches all its rules; a rule's own `enabled` beats it:

```toml
[Html]
enabled = false

[Html.DuplicateId]
enabled = true
```

To change a rule for some files only, give it `include` or `exclude` globs. They follow the EditorConfig syntax (`*`, `**`, `?`, `[abc]`, `{a,b}`): a pattern without `/` matches in any folder, one with a leading or inner `/` is anchored to the folder of the file that holds it.

```toml
[Html.ImgAlt]
exclude = ["**/*.haml", "app/views/legacy/**"]
```

A rule with options takes them in its own table. `max` is a whole number, 0 or more; `style` is one of a few words, and a value that is not one is a problem in the file:

```toml
[Layout.EmptyLines]
enabled = true
max = 2

[Layout.EmptyLinesAroundBlockBody]
enabled = true
style = "empty_lines"
```

### All keys

```toml
root = true                        # stop looking in the folders above
exclude = ["vendor/**", "tmp/**"]  # no checks and no formatting for these files

[erb]
format.enabled = false             # no formatting for ERB
format.align_comments = true       # same as --align-comments
diagnostics.enabled = true         # false: no diagnostics for ERB
disabled_diagnostics = ["Html/ImgAlt", "unclosed-element"]  # rule names, or the codes of 0.10 and earlier

[haml]                             # format.enabled, diagnostics.enabled, disabled_diagnostics
[slim]                             # the same, and: extra_engines = ["mjml"]; Skim files too
[jbuilder]                         # disabled_diagnostics, for Jbuilder and Builder views
```

The language tables take the keys of the `rubyTemplates.<language>.*` settings, in snake case. A key under the wrong table (`extra_engines` under `[erb]`) is reported.

### Which file applies

- The file looks for `.ruby-templates.toml` in the template's folder and every folder above it, nearest first, and stops at one with `root = true`.
- The files merge key by key: the nearest file that sets a key wins. A list (`exclude`, `include`, `disabled_diagnostics`, `extra_engines`) is replaced, not extended. Globs are relative to the folder of the file that holds them.
- The file is stronger than VS Code: precedence is the nearest file, then the VS Code settings (where no file says anything), then `.editorconfig` for the indentation width, then the defaults.
- A rule is on, if it is on by default, unless the nearest file that sets either its `enabled` or its department's `enabled` says `false`, and a formatting rule that is off by default is on when that file says `true`; within that one file, the rule's own `enabled` beats the department's. A root file with `[Html.ImgAlt] enabled = true` and a `legacy/` file with `[Html] enabled = false` therefore leave `Html/ImgAlt` off under `legacy/`. Then the rule's `include` and `exclude` apply, and the rule must exist for the file's language. A file in the global `exclude` gets no diagnostics and is not formatted.

### Problems in the file

A key or a value the server can't read is dropped, and the rest of the file is used. A file that exists but can't be read (not UTF-8, no permission, a folder with that name) is one problem at its first line. Problems show on the `.ruby-templates.toml` itself in the Problems panel, and in the _Ruby Templates_ output, once a template it applies to is open or formatted; they refresh when the file is saved. A `.ruby-templates.toml` above the workspace folders is watched too, if the editor allows it. `ruby-templates check` prints a problem as `file:line:column: warning: message` and exits with 1 (the legacy `ruby-templates-ls --check` prints it but doesn't fail on it), and `format --verbose` prints it too. A file that isn't valid TOML is ignored whole.
