# Built-in checks and formatter: plan

Goal: check and format Slim, Haml and ERB templates with our own Rust code, following only what the languages' official projects define: their documentation, their parsers' and compilers' errors, their changelogs and their test suites; for the HTML that templates produce (the text of `.html.erb`, the output Slim and Haml compile to), the HTML standard (WHATWG). Decision: D13 in `docs/DECISIONS.md`.

Each stage says **what we want**, **what we get** (with output of the official implementation) and **how we compare** against it, so a stage is done by measurement.

## Principles

1. **Official sources only.** A behaviour we implement cites one of the sources in the table below: a README/reference section, a file of the official implementation, a changelog entry or a test of its suite. Nothing else is a source.
2. **Third-party tools are not sources.** slim-lint, haml-lint, erb_lint, Herb (linter, formatter, parser), htmlbeautifier and erb-format are community projects. We don't copy their rules, messages, options, config files (`.slim-lint.yml`, `.haml-lint.yml`, `.erb_lint.yml`, `.herb.yml`) or output formats, and we don't run them.
3. **Checks = what the language itself rejects.** Errors raised by the official parser and compiler, with their messages; syntax the official changelog removed; Ruby that doesn't compile once the official compiler has turned the template into Ruby; for the HTML of ERB templates and the HTML Slim and Haml compile to, what the HTML standard marks as a parse error or a "must". Rails' render-time errors that the source shows unambiguously (`unresolved-render`, `strict-locals`), only in a Rails project of a version that raises them (see [Context](#context-framework-and-versions)). No style rules: the official projects define none.
4. **Format = whitespace only, as the official examples write it.** Indentation by nesting level in the unit the official documentation's examples use (2 spaces), trailing whitespace, final newline. Never a change to what the official compiler produces, except where a stage says so and why.
5. **The official implementations are the oracle.** The official gems run on the developer's machine (isolated install, never in the product) to produce the reference: their errors for the checks, their compiled output for the formatter.
6. **No external tool at runtime**, and no new runtime dependency without a reason in the commit (`CLAUDE.md`).

## Context: framework and versions

What is an error depends on the framework and on the versions a project uses, so every check knows both. They come from the project's `Gemfile.lock` (Bundler's lockfile: each resolved gem as `    name (version)` under `specs:`), the nearest one from the template up.

**Framework**, from the gems in the lockfile:

| Lockfile has                | Framework | Checks                                                                                                                                                                            |
| --------------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `actionview`                | Rails     | language, HTML (ERB) and Rails checks                                                                                                                                             |
| `sinatra` (no `actionview`) | Sinatra   | language and HTML (ERB) checks; no Rails checks: Sinatra renders through Tilt (`erb :index` → `views/index.erb`), with no `render "dir/name"` partial lookup and no strict locals |
| neither, or no lockfile     | unknown   | language and HTML (ERB) checks                                                                                                                                                    |

This replaces today's guess "a file under `app/views` is Rails" (`partials.rs` `views_root`).

**Rails versions** (checked in `actionview` at each tag):

**Template language versions:** `slim`, `haml`, `erubi` versions come from the lockfile too. The plan pins the latest (Slim 5.2.2, Haml 7.5.1, Erubi 1.13.1) and starts there. An older major (Slim 4, Haml 5 and 6) is supported once the oracle runs that major's gem: until then, a project on it gets only the checks the oracle shows behave the same in both majors, and formatting only where the compiled output is unchanged under that major. No lockfile, or a gem missing from it: the pinned version.

**Ruby version:** Rails evals a template with the app's Ruby, whose Prism grammar is that Ruby's own (`<% x = a\n  && b %>` is a syntax error on 3.3 and 3.4, valid on 4.1). The Ruby checks of ERB and Slim therefore parse with the project's Ruby, from the nearest `.ruby-version` (`3.3.6` or `ruby-3.3.6`, first line that is not blank or a comment) from the template up, else the nearest `Gemfile.lock`'s `RUBY VERSION` section (`ruby 3.3.6p108`). Prism 2.0.0 has these grammars: 3.3.x → 3.3 (also older Rubies, which it has no grammar for), 3.4.x → 3.4, 3.5.x and 4.0.x → 3.5, 4.1.x → 4.1, anything newer → latest. A `.ruby-version` that names no CRuby `major.minor` (`jruby-9.4`, `system`, a bare `3`) is skipped for the lockfile's; with no version at all: the latest grammar. The formatter checks with the same version, so it refuses on the errors the server shows.

## How we compare (oracle harness, stage 0)

`bun test/oracle.js <language>` on the developer machine; skips with a message when the gem isn't installed. Isolated install: `GEM_HOME=<tmp> gem install slim:5.2.2 haml:7.5.1 erubi:1.13.1`, plus the engine and filter gems the official docs list (Slim README "Embedded engines" table, the Haml filters' gems), since both compilers load them at compile time. A `LoadError` for a missing engine gem is reported as "dependency missing", never as a template error.

1. **Errors.** For each file, the official parser/compiler's error (message, line, column where it gives one) vs ours. Fixtures: the official test suites' error cases (`slim/test/core/test_parser_errors.rb`, `haml/test/haml/error_test.rb` and the error cases in `engine_test.rb`), plus every template of those suites that compiles (we must report nothing). Target **100%**.
2. **Formatter safety.** For each file we format: the official compiled output before and after is identical (Slim: `Slim::Engine` source with the Rails generator; Haml: `Haml::Engine` source; ERB: see stage 3). Target **100%**: a difference is a bug.
3. **Corpora.** Public apps' views (Forem, Mastodon, rubygems.org, Whitehall, freeats; GitLab for Haml), shallow sparse clones outside the repo: errors as in 1, formatter safety as in 2, idempotence (formatting twice changes nothing more).

Report:

```
slim 5.2.2 vs ruby-templates  (1,203 files)
errors:  official 3, ours 3, same 3
format:  1,203 files, compiled output identical in 1,203, idempotent in 1,203
```

## Stage 1. Slim (5.2.2)

### 1a. Errors

**Want:** our parser (`slim_parser.rs`, a port of `Slim::Parser`) rejects exactly what Slim 5.2.2 rejects, with Slim's message, line and column, parsing with Slim's default options (`README` "Available options": `tabsize: 4`, `default_tag: div`, shortcuts `.` → class and `#` → id, `code_attr_delims`/`attr_list_delims` `()[]{}`, `splat_prefix: *`, all engines enabled).

**Syntax** (README sections, all must parse): line indicators `|`, `|<`, `|>`, `|<>` (5.1.0), `'`, `<`, `-`, `=`, `==` with `<`/`>`; `/`, `/!`, `/[…]`; doctype; closed tags `/`; tag whitespace `<` `>`; inline tags `:`; text content; dynamic content; attribute wrappers; quoted, Ruby and boolean attributes; attribute merging; splat `*` attributes and dynamic tags; default shortcuts; `#{}` interpolation; engines `ruby`, `javascript`, `css`, `sass`, `scss`, `coffee`, `asciidoc`, `markdown`, `textile`, `rdoc` (`less` removed in 5.2.2), with attributes for javascript/css/coffee/sass/scss.

**Errors** (`lib/slim/parser.rb`, verbatim): `Unexpected indentation`, `Malformed indentation`, `Unknown line indicator`, `Illegal shortcut`, `Expected tag`, `Unexpected text after closed tag`, `Invalid empty attribute`, `Expected attribute`, `Expected closing delimiter <d>`, `Unexpected end of file`.

**Removed syntax** (`CHANGES`): the 5.0.0 entries "Remove deprecated whitespace syntax =' etc" and "Remove deprecated syntax", and engines removed in 4.0.0 (except `asciidoc`, registered again in 5.2.2) and 5.2.2 (`less`); each is reported as Slim 5.2.2 reports it (an error above, or rendered as text, whichever the official parser does: checked against the oracle, not guessed).

### 1b. Format

**Want:** re-indentation in steps of 2 spaces per nesting level, the unit of every example in the Slim README. The README (line 114) states that any depth is valid ("If you want to first indent 2 spaces, then 5 spaces, it's your choice"), so formatting is a convention from the examples, never a check: we never report indentation that Slim accepts.

**Rules, each from the README:**

- A nested line moves to its parent's indentation + 2.
- Verbatim text (`|`, `'`): "each following line that is indented greater than the pipe is copied over" and the first line sets the left margin, so continuation lines move with the pipe line, keeping their offset from it.
- Embedded engine bodies, multi-line Ruby (`,` or `\` continuation) and multi-line attribute wrappers move as a block with their first line.
- Trailing whitespace is kept on every line whose output contains it: verbatim text (`|`, `'`, `|<`, `|>`, `|<>`) and its continuation lines, and inline tag text (`p foo   ` compiles to `<p>foo   </p>`); it is removed only on lines whose compiled output doesn't contain it. A single final newline: whitespace-only lines at the end stay, since Slim compiles them, and the empty lines after them collapse into it, since Slim drops them (checked with the oracle, also at the end of `|` text blocks and engine bodies).
- Tabs: Slim reads a tab as `tabsize: 4`; a tab-indented file is converted to spaces only if the compiled output stays identical.
- A file with an error (1a) is not formatted.

**Get:**

```slim
div.card              div.card
    - if user     →     - if user
        h1 = name           h1 = name
```

**Compare:** compiled output identical before and after on the Slim test suite templates and the corpora; idempotent.

**Want:** what `Haml::Parser`/`Haml::Compiler` reject, with Haml's messages (`lib/haml/error.rb`), at Haml's line:

(`cant_run_filter`, `gem_install_filter_deps`, `install_haml_contrib` and `filter_not_defined` are unused in 7.5.1: nothing in `lib/haml` raises them. A filter whose gem is missing fails with a plain `LoadError` at compile time.)

**Syntax** (`REFERENCE.md` sections): plain text and `\`; elements `%`; attributes `{}`, `()`, Ruby 1.9 hashes, boolean and data attributes; `.`/`#` and implicit div; void tags `/`; whitespace removal `>`/`<`; object reference `[]`; doctype `!!!`; comments `/`, `/[]`, `-#`; `=`, `-`, Ruby blocks, `~`, `#{}`, `&=`, `!=`; filters as registered in `lib/haml/filters.rb`: `:cdata`, `:coffee`, `:coffeescript`, `:css`, `:erb`, `:escaped`, `:javascript`, `:less`, `:markdown`, `:plain`, `:preserve`, `:ruby`, `:sass`, `:scss` (REFERENCE.md also documents `:maruku` and `:textile`, which 7.5.1 rejects with `FilterNotFound`); multiline `|`.

**HTML:** the HTML `Haml::Compiler` produces, per WHATWG, as in 1a. Content nested under a void element is reported by the same rule as in 1a if Haml compiles it to an end tag; whether 7.5.1 does (its `autoclose` applies only when nothing is nested) or raises `illegal_nesting_self_closing` is checked against the oracle, not guessed.

**Compare:** `test/haml/error_test.rb`, the error cases of `engine_test.rb`, and `haml-spec` (the implementation-independent Haml spec) plus `templates/` without error: 100%.

### 2b. Format

**Want:** re-indentation to 2 spaces per level, the unit of the `REFERENCE.md` examples. Haml requires one consistent unit per file (`inconsistent_indentation`), but doesn't fix it, so this too is a convention, never a check beyond Haml's own errors.

**Rules, from `REFERENCE.md`:** nesting by indentation ("Ruby Blocks"); filter bodies move as a block with their filter line ("Filters"); `:preserve` and `~` content are left as they are (REFERENCE.md "`:preserve`" and "Whitespace Preservation: `~`"); multiline `|` lines move with their first line; a file with an error (2a) is not formatted.

**Compare:** `Haml::Engine` compiled source identical before and after; idempotent.

## Stage 3. ERB (ruby/erb 6.1.0, Erubi 1.13.1, Rails 8.1.4)

### 3a. Errors

**Want:** what fails when Rails compiles the template:

- Tags per Erubi's regexp (`lib/erubi.rb`, indicator `(={1,2}|-|\#|%)?`): `<% %>`, `<%- %>`, `<%= %>`, `<%== %>`, `<%# %>`, `<%% %>` (literal), `-%>` trim with `trim: true` as Rails sets it. An unclosed `<%` with no `%>` after it is text to Erubi, not an error; in an HTML template that text is an HTML parse error (the HTML item below). When a later `%>` exists, Erubi's lazy match runs on to it and the generated Ruby fails: that is a Ruby syntax error (next item).
- Ruby: the source Erubi generates with Rails' options must be valid Ruby; Prism's error message is reported at the template line it comes from, and every location Prism gives is shown (for an unclosed `if`, the `if` as well as the end of the file). Example: `<%= if x %>y<% end %>` compiles to `@output_buffer << ( if x ).to_s; …; end`, on which Prism 2.0.0 reports ``expected `then` or `;` or '\n'`` and ``expected an `end` to close the conditional clause``.
- Rails: the strict locals magic comment `<%# locals: (…) -%>` must hold a keyword-only parameter list: Rails rejects positional parameters (`template.rb`: "Locals can only be set as keyword arguments.").

- HTML (WHATWG, ERB templates with an HTML host): a `<%` Erubi leaves as text, which the tokenizer reports as `invalid-first-character-of-tag-name` (13.2.5.6, `<` followed by `%`); an end tag with no open element, an end tag closing a different element, an element never closed (13.2.2, 13.2.6.4.7; void elements 13.1.2 and optional end tags 13.1.2.4 are not errors), `<img>` without `alt` (4.8.3, 4.8.4.4), a static `id` used twice (3.2.6). The standard gives no message text for the three tag errors (the parser recovers silently), so those messages are ours and cite the section; `invalid-first-character-of-tag-name` is the standard's own error code; the others quote the standard's "must".

**Compare:** Erubi + Rails handler output parsed by Prism 2.0.0 on the corpora: same files with errors, same lines, same messages.

### 3b. Format

**Want:** indentation of nested HTML elements and ERB blocks (`<% if %>` … `<% end %>`, `do … end`) by 2 spaces per level, as in the examples of the Rails Guides "Action View Overview" and "Layouts and Rendering"; HTML nesting per WHATWG (void elements 13.1.2 open nothing, optional end tags 13.1.2.4 are closed where the standard closes them).

**What changes in the output:** ERB copies the template's text, indentation included, into the HTML it renders. Re-indenting therefore changes whitespace in the rendered HTML; it never changes Ruby, tags or attributes. Content whose whitespace is visible is left as it is: `<pre>`, `<textarea>`, `<script>`, `<style>` bodies, multi-line ERB tags' Ruby, text with significant leading spaces. The compiled-output comparison for ERB is therefore: identical after removing whitespace at the start of text lines outside those elements.

**Compare:** that comparison on the corpora; idempotent.

## Not from official sources (needs a decision)

What we have today, with its official source or none. Items still marked open or remove stay as they are (not extended) until decided here. Decided: HTML checks in ERB are in scope, citing WHATWG; `unresolved-render` and `strict-locals` stay, gated by framework and version.

Decided (2026-10-25):

1. **Fold.** Every code marked "fold" goes into `ruby-syntax` (ERB) and the Ruby check of 1a (Slim), with Prism 2.0.0's messages at the template lines they come from. The old codes are removed in a `BREAKING CHANGE`; entries for them in `disabledDiagnostics` are ignored.
2. **Remove, false positives and duplicates:** `malformed-tag`, `prefer-image-tag`, Haml `bad-dedent`, the Ruby variant of Haml `illegal-nesting`, the `(` case of Haml `unclosed-attribute`, Slim `inconsistent-indent`.
3. **Remove, real bugs without an official source:** `silent-output-helper` (ERB, Slim) and `unsafe-output`; no exception to principle 1. The first case of `unclosed-tag` stays: it has a source in WHATWG (3a).
4. **HTML of Slim and Haml output** is in scope, citing WHATWG (1a, 2a); `void-children` stays with that source.
5. **ERB formatting changes rendered whitespace**, accepted as 3b describes: re-indentation outside `<pre>`, `<textarea>`, `<script>`, `<style>`, multi-line ERB tags' Ruby and text with significant leading spaces, compared with leading whitespace on text lines removed.
6. **Editor and `.editorconfig` give the Slim, Haml and ERB formatters only the indentation width (default 2); they always write spaces and keep the file's line endings** (Slim decided 2026-10-26, Haml 2026-10-27, ERB 2026-10-28). For Haml, empty and whitespace-only lines at the end collapse into one final line ending (Haml strips the template), and the `.haml-lint.yml` formatting keys stop applying.
7. **Ruby checks parse with the project's Ruby version** (`.ruby-version`, else `Gemfile.lock` `RUBY VERSION`), the latest grammar when none (decided 2026-10-27).
8. **ERB formatting, the whitespace beyond re-indentation** (decided 2026-10-28): trailing whitespace of text lines is removed, under the same exceptions as indentation (5), and the compiled-output comparison also ignores it; the indentation of attribute lines inside a multi-line start tag may change (whitespace between attributes, never inside a value); a missing final newline is not added; the inside of an HTML comment is left as it is (only the line holding `<!--` is re-indented).
9. **Editor settings of stage 4** (decided 2026-10-28): the indentation width stays the editor's and `.editorconfig`'s (6), with no setting of its own; each language gets `rubyTemplates.<erb|haml|slim>.diagnostics.enabled` and `rubyTemplates.<erb|haml|slim>.format.enabled` (both on by default); every diagnostic's `source` is the file's language (`erb`, `haml`, `slim`), HTML and Rails checks included. The built-in ERB formatter is the default (`rubyTemplates.erb.formatter: builtin`); `erb.format.enabled` turns it off.
