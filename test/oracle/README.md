# Oracle harness

Compares the official template engine with `ruby-templates` (see `docs/LINT_PLAN.md`, "How we compare"). Stage 0 measures today's code: mismatches are printed, not failed.

## Install

Isolated gems, so the pinned versions don't touch the system Ruby:

```sh
export GEM_HOME=/tmp/oracle-gems GEM_PATH=/tmp/oracle-gems PATH=/tmp/oracle-gems/bin:$PATH
gem install slim:5.2.2 haml:7.5.1 erubi:1.13.1 prism:1.9.0 prism:2.0.0 actionview:8.1.4 minitest:5.27.0
gem install actionview:7.0.8.7 actionview:7.1.5.1 actionview:8.0.1 actionview:8.0.2   # for `context`
```

Haml 7.5.1 mis-parses nested hashes (`%div{:data => {:a => 1}}`) with prism 2.x, which `gem install haml` resolves to, so `haml.rb` activates prism 1.9.0 and the harness skips Haml when that version doesn't load. Slim doesn't use prism. The ERB oracle needs prism 2.0.0 next to it (the plan's Ruby parser), so both versions stay installed and each script activates its own; `erb.rb` also activates `minitest < 6`, because minitest 6 (an ActiveSupport dependency) wants prism ~> 1.5.

Embedded engines (Slim README "Embedded engines", the Haml filters) need their own gems; without one the case is reported as "dependency missing", never as a template error.

## Run

```sh
cargo build --release --manifest-path server/Cargo.toml
bun test/oracle.js slim          # or haml, erb, context; VERBOSE=1 lists every mismatch
```

Without the pinned gem version (Slim 5.2.2, Haml 7.5.1) on `ruby` it prints a skip message and exits 0.

- `test/oracle/slim.rb`: compiles the template on stdin with Slim's defaults and prints `{"error": {message, line, column, slim_column}}`, `{"dependency_missing": gem}` or `{"source": ruby}`.
- `test/oracle/slim_cases.rb`: replays `test/core/*.rb` of the Slim checkout against a recording stub and prints the templates they render. Tests that need non-default options are skipped and counted.
- `format:` line: for each case Slim compiles and we don't flag, `ruby-templates format` runs, then `slim.rb --rails` compiles the text before and after (the Railtie's generator and options, without ActionView: only source is generated) and they must be identical; formatting the result again must change nothing. Cases with an error of ours aren't formatted and are counted apart.
- Corpora: pinned public apps listed in `corpora` in `test/oracle.js` (name, url, full commit, sparse paths). Each is fetched shallow and blob-less at its commit into `$ORACLE_CACHE/corpora/<name>-<sha7>` and reused; the files keep their real paths there (so the project context is the app's), and `ruby-templates` only reads them (`format` goes to stdout via `--stdin-filepath`). Each corpus gets its own report block with the same `errors:` and `format:` lines; a file the official engine can't compile for a missing engine gem is skipped. Today: freeats (Slim) at `aee7cf7`, mastodon (Haml) at `f045f6b`; GitLab (Haml) is left out as too big for a routine run.
- The official checkout (tag `v5.2.2` of Slim, `v7.5.1` of Haml, shallow) is cloned once into `$ORACLE_CACHE`, default `$TMPDIR/ruby-templates-oracle`, as `slim-5.2.2` / `haml-7.5.1`.
- Haml: `haml.rb` takes the error Haml::Engine would turn into code that raises (Haml reports no column); its `line` is 1-based, Haml's own 0-based `Error#line` is kept as `haml_line`. `--rails` uses the options of `Haml::RailsTemplate` (that class needs ActionView, so they are repeated in `haml.rb`). `haml_cases.rb` replays `test/haml/**/*_test.rb` against a recording stand-in for `test_helper.rb` (every `Haml::Engine`/`Haml::Parser` call is a case; `EngineTest::EXCEPTION_MAP` supplies the expected messages), and adds `haml-spec/tests.yml` and `templates/*.haml`. Options other than `escape_html`, `escape_attrs`, `filename` and `file` count as non-default and are skipped.
- `error.column` is a 0-based UTF-16 offset produced by `slim.rb` from Slim's character column (`slim_column`); the CLI prints 1-based columns, so they are compared with a +1.
- ERB (`erb.rb`): corpora only, since Erubi's tests check output, not errors. It builds a real `ActionView::Template` (Rails 8.1.4, format from the file name, no view or lookup context needed) and parses the method source Rails would `module_eval` (`Template#compiled_source`: Erubi with `trim: true` and `@output_buffer`, wrapped in `def …(local_assigns, output_buffer, &_)`) with Prism 2.0.0, so class/module/constant definitions in a tag are errors as in Rails. Strict locals: a bad `locals:` signature is reported at the comment's line, and non-keyword locals through Rails' own `Template#compile` (its `ArgumentError`). Lines: the template's first line is the line after the wrapper's `@virtual_path = …`; errors past the template (the lines Erubi and the wrapper add) are clamped to its last line, and the wrapper's own unclosed-`def` error is dropped. Prism's column is in the generated line, which doesn't map back, so only line and message are compared. A file agrees when each official error has an error of ours with the same line and message; the `lines:` line counts files where an official error's line also has an error of ours, and files where only HTML-looking errors of ours appear. Formatting (3b): for each file Rails compiles and we don't flag, `erb.rb --normalize` compiles the template with the leading whitespace of its text lines removed (only on lines that start in HTML text: not inside a tag or attribute value, comment, `pre` (nested ones counted), `script`, `style`, `textarea`, or an ERB tag, found with Erubi's own regexp); a file whose Ruby builds such an element (`content_tag :pre`, `javascript_tag`, `raw "<pre>"`, …) is counted as not compared, before and after `ruby-templates format`; the method sources must be identical, and a second format must change nothing. The `format:` line also counts the files the formatter changed. Corpora: forem, rubygems.org, whitehall (`app/views`, `app/components`, every `.erb`).
- `context` (stage 0b): the harness writes a small app per fixture into a temp dir: a `Gemfile.lock` for actionview 7.0.8.7, 7.1.5.1, 8.0.1, 8.0.2, for Sinatra (no actionview) and none at all, a strict-locals partial `_card` (`locals: (a:, b:)`), a `_none` (`locals: ()`) and one template per `render` call (12 of them: missing partial, the four locals sets, the shorthand form, a valid render, `locals: ()` with and without locals), so each Rails error is attributable. `context.rb <actionview version> <app> <template>` renders it with that actionview (`ActionView::Base.with_empty_template_cache`, a `LookupContext` on `app/views`) and prints the first line of the error and the template line it came from; the app directory is removed from the message, as ours is app-relative. Our side is `ruby-templates check` on the same files, matching diagnostics by message and line. `MissingTemplate`'s message goes on with formats and search paths that depend on the app, so only the part before `with` is compared (counted as not compared). The render sits on a different template line in each file. Only on 7.0, where the `locals:` line is a comment, a `NameError` from the partial's own body (an undefined local) has no render check and is counted as not compared; any other Rails error is an official error our checks must match. Ours are warnings (a prediction of the render-time error), so `same` says the severity it agreed as. Sinatra and no lockfile have no Rails render (`official n/a`): ours must report none of these diagnostics.
